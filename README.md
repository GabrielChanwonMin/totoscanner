# 토토스캐너

베트맨 프로토 승부식 픽의 적정배당·기대값(EV)을 계산한다.
웹앱은 Artifact로 배포돼 있고, 이 폴더는 **데이터를 만들어 넣는 쪽**이다.

```
totoscanner.html      배포된 웹앱 원본 (수정 후 Claude Code에 "재배포해줘")
collector/            베트맨 수집기  ← 회차마다 실행
engine/               Dixon-Coles 학습 + 백테스트  ← 시즌 중 가끔 실행
```

---

## 0. 쓰는 법 — 더블클릭 하나

바탕화면 `토토스캐너` 폴더의 **`토토스캐너 실행.command`** 를 더블클릭한다.

1. 그 시점의 베트맨 회차·배당을 받는다
2. 해외 컨센서스 배당을 붙인다
3. 결과를 **클립보드에 담고** 앱을 브라우저로 연다
4. 앱에서 `경기 입력 › 회차 불러오기` 에 **⌘V** 하고 `해석해서 불러오기`

상시 실행되는 게 아니라 **네가 누를 때만** 돈다. 맥 백그라운드에 아무것도 안 남는다.

> 처음 더블클릭할 때 "확인되지 않은 개발자" 경고가 뜨면
> 파일을 **우클릭 › 열기** 로 한 번만 열어주면 그 다음부터는 그냥 열린다.

특정 회차를 찍고 싶으면 터미널에서:
`cd ~/Desktop/토토스캐너/collector && python3 collect_betman.py 260109`

### 해외 컨센서스 배당
**football-data.co.uk fixtures.csv**(무료)에서 가져온다. 백테스트에 쓴 것과 같은 소스·같은 컬럼이라
검증된 수치가 그대로 적용된다. 유료 API 구독은 필요 없다.

- `AvgH/AvgD/AvgA` (여러 북메이커 평균) → 승무패 컨센서스
- `Avg>2.5 / Avg<2.5` → 언더오버 컨센서스
- 핸디캡·SUM 은 **같은 경기의 스코어행렬에서 파생**된다

한계는 정확성이 아니라 **시점**이다. fixtures.csv 는 보통 경기 1~2일 전에 채워진다.
회차 마감이 그보다 이르면 그 경기는 앱에서 직접 입력해야 한다.
해외 배당이 없으면 **등급이 아예 안 매겨진다** — 모델 단독 픽은 백테스트 ROI −12% 였다.

### 파생 마켓
베트맨은 한 경기를 승무패·핸디·언오버·SUM 으로 쪼개 내는데 해외 배당은 승무패에만 붙는다.
앱은 경기마다 **스코어 확률행렬 하나**를 만들어 나머지를 거기서 뽑는다. 실경기 1,814경기로 검증했다.

| 파생 | 결과 |
|---|---|
| 핸디캡 −1.0 | 예측 24.0/19.8/56.2% vs 실제 23.5/19.8/56.7%, ECE 0.013 |
| 언더오버 2.5 | Log loss 0.67583 vs 실제 O/U 시장 0.67578 (사실상 동일) |
| SUM 홀짝 | 예측 홀 48.6% vs 실제 47.3%, ECE 0.014 |

총득점 파생은 로짓 sd 0.19 만큼 흔들리고 오버를 0.087 낮게 본다 → 앱이 보정하고
불확실성을 더 크게 잡는다. 목록의 `파생` 배지가 그 표시다.

## 1. 자동 채점 — 네가 적을 건 없다

`토토스캐너 실행` 한 번에 이 순서로 돈다.

```
[1] 베트맨 회차·배당 수집
[2] 해외 컨센서스 배당 붙이기
[3] 이번 회차 예측을 파일로 기록   ← predict_round.py
[4] 지난 회차 자동 채점            ← settle.py
[5] Supabase 업로드
```

경기가 끝나면 football-data 가 결과를 올리고, 다음 실행 때 `settle.py` 가
**예측 ↔ 실제 결과를 자동으로 맞춰 채점**한다. 앱의 `성적표` 탭에 이렇게 쌓인다.

- 앱이 예상한 적중 수 vs 실제 적중 수
- 확률 보정 — "70%"라 한 픽이 실제 몇 % 맞았나
- 등급별 실제 ROI (🟢추천 / 🟡관심 / ⚪참고)
- 베트맨 배당 구간별 적중·실패
- 앱(해외 컨센서스) vs 자체 모델 — 누가 더 맞았나

> 레이팅 학습 기간과 겹치는 경기는 모델 비교에서 자동으로 뺀다.
> 안 그러면 모델이 이미 본 경기로 채점돼 실력이 부풀려진다.

### 엔진이 두 벌인 이유
예측을 브라우저 없이 남기려면 파이썬에도 같은 엔진이 필요하다(`engine/predict.py`).
JS 와 갈라지면 기록과 화면이 달라지므로 대조기를 뒀다.

```bash
cd ~/Desktop/토토스캐너 && python3 engine/parity_check.py
```

엔진을 손댔으면 반드시 돌려라. 실제로 이 대조기가 `ratings.json` 이 앱과
어긋난 걸 잡아냈다.

## 2. 피드백 루프 — 무엇이 학습되고 무엇이 안 되는가

| | 학습되나 | 왜 |
|---|---|---|
| **팀 공격·수비력** | ✅ `refresh_ratings.py` | 회차마다 실경기 결과가 40경기씩 쌓인다. 표본 충분 |
| **확률 보정 상태** | ✅ 기록 탭 `자체 채점` | 앱이 "70%"라 한 픽이 실제 몇 % 맞았는지 누적 |
| **EV·앙상블 가중치** | ❌ 일부러 안 한다 | 회차당 등급 픽이 1~2개다. 20~30개로 가중치를 고치면 노이즈를 학습한다 |

세 번째가 핵심이다. 백테스트 5,238경기로도 최적 시장가중치는 1.00 이었다.
네 픽 30개로 그걸 뒤집으려 하면 반드시 손해가 난다. 그래서 §6.7 이 적중률 대신 CLV 를 쓰라고 한 거다.

## 4. 베트맨 수집 구조 (2026-09-11 확인)

Playwright 불필요. 순수 HTTP 2회.

```
1) GET  /main/mainPage/gamebuy/gameSlip.do?gmId=G101&year=2026&gmTs=260108   → JSESSIONID
2) POST /buyPsblGame/gameInfoInq.do
   Content-Type: application/json; charset=UTF-8
   {"gmId":"G101","gmTs":260108,"gameYear":"2026","_sbmInfo":{"debugMode":"false"}}
```

응답에서 쓰는 것:

| 필드 | 내용 |
|---|---|
| `compSchedules.keys` / `.datas` | 경기 목록 (컬럼형). 리그·팀·팀ID·킥오프·마켓·기준선·배당·한경기구매 여부 |
| `currentLottery` | 회차 번호, 발매 시작/마감 시각, 판매 상태 |
| `tooltipList` | **베트맨이 공개하는 배당 변동 이력** (변경 전/후 배당, 변경 시각) |

주의할 점
- `betNm` 으로 마켓을 판별해야 한다. `betTypNm` 만 보면 **전반전 마켓이 정규 마켓과 섞인다**
- 전반 마켓은 90분 정산이 아니라 제외한다. 소수핸디캡(무승부 없음)도 앱이 아직 미지원
- 회차마다 5대 리그가 없을 수 있다 (A매치 휴식기엔 K리그·남미 위주)
- 배당은 발매 시작 시각 전에는 전부 `0.0` 이다
- 요청 간격 5초, 재시도는 지수 백오프. 회차당 2회 요청이면 충분하다

### 팀명 매칭
베트맨은 정식 클럽명을 쓴다(`VfB슈투트가르트`, `토트넘 홋스퍼`, `릴OSC`).
`match_teams.py` 가 접두·접미어와 창단연도를 떼고 매칭하며,
확정된 결과는 **베트맨 팀ID 기준**으로 `team_aliases.json` 에 영구 저장된다.
2026-09-11 108회차 기준 고유 팀 86개 100% 매칭, 오매칭 0건.
새 팀이 안 잡히면 실행 시 안내가 뜨고, 그 줄을 `team_aliases.json` 에 넣으면 끝이다.

## 5. 용량

실측이다. 걱정할 수준이 아니다.

```
전체 폴더            약 0.7 MB
스냅샷 1개           약 88 KB
실행 1회당 늘어남    약 88 KB
1년 (회차당 1~2회)   약 15 MB   ← 아이폰 사진 5장 크기
```

실행할 때마다 **스냅샷은 최근 60개만 남기고 자동으로 지운다.** 그 이상 안 늘어난다.
저장한 픽·정산 기록은 애초에 네 맥이 아니라 앱(웹)에 저장되고, 친구와 공유된다.

스냅샷을 로컬에 남기는 이유는 하나다 — **베트맨 배당이 시간에 따라 어떻게 움직였는지**가
지연 배당 탐지와 편향 분석의 유일한 자산이라서다. 필요 없으면 `collector/snapshots/` 를
통째로 지워도 앱은 그대로 돌아간다.

## 6. 친구에게 주는 법

**방법 A — 앱 주소 공유 (권장)**
앱을 열고 **공유 메뉴에서 친구를 지정**해 초대한다. 기본이 비공개고, 이 앱은 데이터베이스를
쓰기 때문에 **"링크 아는 사람 누구나" 로는 아예 공개할 수 없다.** 실수로 퍼질 위험이 없다.
공유가 되면 저장한 픽·정산 기록이 승인된 회원끼리 실시간 공유된다. 인원 제한은 없다.

**방법 B — 파일로 주기 (공유가 안 될 때)**
`친구용 토토스캐너.html` 파일 하나를 카톡·메일로 보내면 된다. 더블클릭하면 브라우저에서 열리고
설치도 로그인도 필요 없다. 계산·조합·방법론 전부 똑같이 돌아간다.
다른 점은 하나뿐 — **기록이 친구 브라우저에만 저장되고 너와 공유되지 않는다.**

둘 다 회차 데이터는 네가 넘겨야 한다. `토토스캐너 실행.command` 로 복사한 JSON을
카톡으로 보내주면 친구가 `경기 입력 › 회차 불러오기` 에 붙여넣으면 된다.
